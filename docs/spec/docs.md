# 文档规范

> 本文件是 [`AGENTS.md`](../../AGENTS.md) 索引下的规范之一。
> 目的：让文档**分模块、可定位、不过载** —— 一个文件讲一件事，讲不下就拆。

---

## 1. 一个模块一个文件夹，一个文件一件事

**目录结构**（`docs/spec/` 下）：

```text
docs/spec/
├── docs.md  workflow.md  git.md  comments.md   ← 跨模块的通用规范，平铺
├── agent/                                      ← 一个模块一个文件夹
│   ├── module.md            入口：子系统地图、硬约束、禁忌
│   ├── features.md          功能清单（功能状态的单一事实来源）
│   └── display.md / display-lifecycle.md / encode.md …
└── tech-stack/
    ├── overview.md          入口：总览
    └── pc.md / pc-ui.md …
```

- **一个模块一个文件夹**：同一模块的规范全放进该文件夹，**不平铺在 `docs/spec/` 根**；
  只有**跨模块**的通用规范（工作流 / git / 注释 / 本文件）才平铺。
- 文件夹内的**入口文件**命名：模块规范用 `module.md`，主题总览用 `overview.md`。
- 一个文件**只讲一件事**；相关但独立的部分（如"显示源"与"它的生命周期"）各自成文件。
- 跨文件的**结论**只允许**一行摘要 + 链接**，细节留在各自文件。
- 正文里引用条目用**文件夹限定的短形式**：`agent/display.md`、`tech-stack/overview.md`。

---

## 2. 单文件上限（硬性）

| 文档类型 | 上限 | 超出怎么办 |
|---|---|---|
| 规范文档（`docs/spec/`） | **200 行 / 12 KB** | **必须拆分** |
| 索引类（`AGENTS.md`、`code-map.md`） | 200 行 | 同上；索引只放路由信息，不放细节 |
| 说明文档（`docs/` 根，如 `prototype.md`） | 200 行 | 拆到 `docs/spec/` 或另建同级文件 |
| 方案文档（`docs/plans/`） | 不设行数上限 | 但必须**一次决策一个文件**，不堆无关内容 |

**拆分方式**：

1. 把**内聚的子主题**整段提成同级新文件（例：`tech-stack/overview.md` → `tech-stack/pc.md`）；
2. 父文件里只保留 **1～3 行摘要 + 链接**，**不复制细节**；
3. 在 [`AGENTS.md`](../../AGENTS.md) 索引与 [`docs/code-map.md §6`](../code-map.md) 登记新文件。

> 上限是"必须拆"的红线，不是目标值：能一屏看完最好。

---

## 3. 引用规则

- 指本仓库文档用**相对路径链接**，并在正文点明小节：`[tech-stack/pc.md](tech-stack/pc.md) §2`。
- 规范写「**应当如此**」，方案写「**这次怎么做**」—— 不要把方案内容抄进规范。
- 指外部（原型等）**只允许经** [`docs/prototype.md`](../prototype.md)（见 [`AGENTS.md`](../../AGENTS.md) 红线 4）。

---

## 4. 变更与登记

- 新增 / 改名 / 移动文档后，**同一次改动内**更新：`AGENTS.md` 索引 + `docs/code-map.md §6`。
- 规范类文件用「变更记录」**追加**，**不删旧结论**（示例见 `tech-stack/overview.md §6`）。
- 方案文档（`docs/plans/`）写完即冻结；实际偏差另建文件，不回头改。
