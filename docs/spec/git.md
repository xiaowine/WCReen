# Git 规范

> 本文件是 [`AGENTS.md`](../../AGENTS.md) 索引下的规范之一。

---

## 1. 默认禁止一切 git 写操作

以下命令**只有当用户当次明确要求**时才可执行：

`commit` · `amend` · `rebase` · `merge` · `cherry-pick` · `push` · `tag` ·
`reset --hard` · `checkout --`（覆盖改动）· `stash drop` / `stash pop` · `branch -D` ·
`clean -fd`

用户**没有提及**提交 → **不提交**。不要用「顺手提交一下」「保持提交历史整洁」之类的理由自行发起。

---

## 2. 授权只对当次请求生效

- 用户说「提交」→ 只完成**这一次**提交。
- 提交完成后立即回到**禁止状态**：后续对话**不得主动提交**，必须等用户**再次**明确要求。
- 不要把一次授权推广成「本会话内都可以提交」，也不要推广到 push / tag 等未被要求的动作。

---

## 3. 提交内容纪律

- **只 stage 与当次任务相关的文件**；禁止 `git add -A` / `git add .` 裹入无关改动。
- 工作区里与本任务无关的既有改动（含用户自己的未提交修改）**保持原样**：
  不处理、不提交、不还原、不 stash。
- 提交前先确认待提交文件清单与任务范围一致。

---

## 4. 历史与其他

- 除非用户明确要求，**不修改历史**（`amend` / `rebase`）、**不打标签**、**不推送**。
- 只读的 git 命令（`status` / `diff` / `log` / `show`）随时可用，不受本规范限制。
- 提交信息建议：中文，说明「做了什么 + 为什么」；避免 `fix` / `update` 这类无信息量的短语。
  （属建议，非强制。）

---

## 5. 授权示例

| 用户说 | 允许 | 允许范围 |
|---|---|---|
| （未提及 git） | ❌ 什么都不做 | — |
| 「提交这次的改动」 | ✅ 一次 commit | 只此一次；不 push、不 amend |
| 「提交并推送」 | ✅ commit + push | 只此一次 |
| 上一轮已提交，本轮未提及 | ❌ 什么都不做 | 等待用户再次要求 |
