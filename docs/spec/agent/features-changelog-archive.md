  F1 已定，其余待讨论。明确 **F8 是参数收纳方而非前置**。

  （枚举可启动应用 / 打开目标应用），均可在**任意时刻**下发；枚举**无屏也能用**且带
  `forceRefresh`；agent **不记忆**目标应用（交 PC）。
- **2026-10-06 实机验证**：**F1 与 F2 均已实机验证**（F1 验收判据 1–5 全过；F2 的 V1–V6 全有结论）。
  F1 细节拆出 [`agent/display-flags.md`](display-flags.md)，F2 枚举细节拆出
  [`agent/launch-enumerate.md`](launch-enumerate.md)。
- **2026-10-06 决定**：`DESTROY_CONTENT_ON_REMOVAL` 升为**固定必须位**（原 PC 可配）⇒ F1 的
  flags 变为**必须位 7 / PC 可配 2 / 派生 1 / 不设 7**。
- **2026-10-06 决定**：**PC 侧限单实例**（F2）—— 同一 App 任一时刻只存在一份，屏内换页由 App
  自身导航负责；agent 不加 `--activity-multiple-task`。协议因此**不需要"复用/新建"字段**。
- **2026-10-06**：**F3 部分定稿**（[`agent/encode.md`](encode.md) §2）—— 编码器能力探测的取法、
  本机实测参考值、**并发路数协商规则 `min(PC 上限, 系统声明值)`**；F3 其余 5 项仍待讨论。
- **2026-10-06**：**F3 续**（[`agent/encode.md`](encode.md)）—— **低延迟一律开启**（§3，实测为 no-op）、
  **码率由 PC 二选一表达且 agent 不自主改**（§4）；F1 新增**刷新率**参数（PC 选、缺省 60、会话内固定）。
- **2026-10-06 决定**：**参数载体** —— 建屏参数（画质 / 编码、**屏行为 flags**、DPI 与屏名）集中在一条
  **「申请屏幕」指令**里、由 PC 选择；**建屏与连接建立解耦**（见 [`agent/display.md`](display.md) §2.0）。
- **2026-10-06 决定 + 实测**：**F3 格式组**（[`agent/encode.md`](encode.md) §5）—— 选择规则统一为
  「优先默认值 → 不支持则退到第一个支持的 → **绝不退软编**」（codec 优先 H.264、位深优先 8-bit、
  profile 优先 High/Main）；**色彩元数据**实测确认 `MediaFormat` 报的值不可信、码流 VUI 自洽。
  另立**全局规则**「**不依赖默认值**」：协议可缺省，**代码必须显式设置 + 回读确认**
  （[`workflow.md`](../workflow.md) §4）。
- **2026-10-06**：新增 [`agent/encode-capability.md`](encode-capability.md) —— 编码器能力**实测快照**
  （清单 / 格式组枚举 / 范围与步进 / 声明并发 / 缺省解析结果 / 边界坑 / **可复现测法**）；
  `encode.md` §2.2 只留指针（**规范与快照分离**：快照换设备即作废）。
- **2026-10-06 决定 + 实测**：**尺寸与帧率的校验规则**定稿（[`agent/encode.md`](encode.md) §2.5）；
  **并发验证跑完**（§2.6 + 快照 §4.1）—— 声明 **16**，但**1440×3200@60 实测只有 7 路**，
  且**与帧率无关**；失败形态为明确抛异常、无静默软编；并记下"**start 成功 ≠ 能用**"。
- **2026-10-06 决定 + 实测**：**F3 第 3 项收口** —— 帧率 = 刷新率（`KEY_FRAME_RATE` 同步）、
  关键帧间隔默认 **1s**、`PREPEND_HEADER_TO_SYNC_FRAMES` **固定为 1**（实测每个 IDR 自带 SPS/PPS）；
  码率表达**系数优先于固定码率**，**模式（VBR/CBR）为独立参数**（缺省 VBR；实测不支持 CQ；
  **`KEY_BIT_RATE` 必填** ⇒ 不存在"交给编码器自动算"）。
- **2026-10-06 定稿**：**F3 第 4 + 6 项合并**为「**静止态可解码性**」（其后修订为**不需要缓存 IDR**，
  详见 [`agent/encode-lifecycle.md`](encode-lifecycle.md) §1）。
- **2026-10-06 定稿**：**F3 第 5 项** → **参数变更一律重建、不存在热改**
  （[`agent/encode.md`](encode.md) §7；撤销原「码率热改」，`PARAMETER_KEY_VIDEO_BITRATE` 不再使用）；
  **传输侧缓存 IDR 改为目前不做**（§6.7：所有接入时点都伴随换面 ⇒ 都有新鲜 IDR）。
  **F3 六项全部定稿。**

  「**换面 + `REQUEST_SYNC_FRAME`**」一条手段覆盖全部四类"需要 IDR"的时点，
  且无 App 副作用（[`agent/encode.md`](encode.md) §6.7）。
- **2026-10-06 定稿**：**色彩字段缺省**按通用规则推导（优先 BT709+LIMITED+SDR_VIDEO，
  依据 = 虚拟屏是 SDR + 内容是 sRGB）；**10-bit 与 HDR 明确不做**

  对屏幕内容不浪费码值）；明确色彩值经**能力表（可选值+缺省）**与**回报（实际生效值）**
